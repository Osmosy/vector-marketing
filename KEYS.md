# Ключи и доступы

Какие переменные окружения нужны агентам, что без них не работает и где взять.
Секреты сюда не пишутся никогда: только имена переменных и порядок получения.

## Как это устроено

Установщик профиля читает `env_requires` из `distribution.yaml` и на установке
печатает по каждой переменной `required` / `needs setting`, а также создаёт
`.env.EXAMPLE`. Манифест собирается **из карты навыков** (`scripts/build_profiles.py`,
`ENV_BY_SKILL`): агенту попадают только те переменные, которые реально нужны его
навыкам. Поэтому ключ Wordstat запрашивается у `seo`, `content`, `yandex-direct`,
`avito`, `market-research` — и не запрашивается у остальных.

Проверить, что требует конкретный профиль:

```bash
cat dist/<agent>/distribution.yaml          # env_requires агента
hermes -p <agent> doctor                    # после установки: что не задано
```

## Обязательные для всех

| Переменная | Обязательна | Где взять | Что без неё |
|-----------|-------------|-----------|-------------|
| `DEEPSEEK_API_KEY` | да | https://platform.deepseek.com — API Keys | агент не запустится: нет модели |

Ключ модели не обязательно DeepSeek — в Hermes можно задать другого провайдера
(`hermes -p <agent> setup model`). В манифесте DeepSeek стоит как пример,
потому что дистрибутив намеренно не несёт `config.yaml`.

## Опциональные

| Переменная | Обязательна | Где взять | Что без неё |
|-----------|-------------|-----------|-------------|
| `HERMES_GATEWAY_TOKEN` | нет | настройка gateway в Hermes | нужен только при работе через мессенджер-канал; в CLI не требуется |

## По навыкам

### Семантика Wordstat — `skills/yandex-wordstat`

Нужны у агентов: `seo`, `content`, `yandex-direct`, `avito`, `market-research`.

| Переменная | Обязательна | Где взять |
|-----------|-------------|-----------|
| `WORDSTAT_API_KEY` | да для этих агентов | Yandex Cloud: сервисный аккаунт с ролью `search-api.webSearchUser` → создать API-ключ (значение показывается один раз) |
| `WORDSTAT_FOLDER_ID` | да для этих агентов | Yandex Cloud: ID каталога, ровно 20 символов (`b1g…`) — без пробела из интерфейса |

Порядок: создать сервисный аккаунт → выдать роль → создать API-ключ → взять ID
каталога → пополнить баланс каталога. Подробно с проверочным `curl` и кодами
ошибок: `skills/yandex-wordstat/references/api-contract.md`.

Ограничения API: статистика — 100 запросов в час, ответ до 250 фраз; бюджет
прогона скрипт держит сам. Без ключа навык не «сломается», а честно скажет
«нет ключа API» и какие переменные задать.

### GEO-прогон — `skills/geo-visibility`

Ключ задаётся **в конфиге прогона**, а не в окружении профиля: поле
`api_key_env` называет переменную, из которой скрипт читает ключ. Для локальных
моделей (`http://127.0.0.1:11434`) ставится пустая строка — эндпоинт без ключа.

| Провайдер | Переменная | Примечание |
|-----------|-----------|-----------|
| Облако (пример) | по вашему выбору, напр. `DEEPSEEK_API_KEY` | любой OpenAI-совместимый эндпоинт |
| Локальные модели (ollama) | `""` (без ключа) | `base_url: http://127.0.0.1:11434` |

Требуется минимум 2-3 независимые модели: замер по одной — не метрика, а
отдельное мнение. Устаревшее имя модели отдаёт HTTP 410 «was retired»,
заблокированный по политике ключ — 401/403: и то и другое попадает в
`callsFailed`, а не в «бренд не найден».

### Посевы статей — `skills/article-distribution`

Секретов не требует: журнал и UTM-разметка работают локально.

## Прочие сервисы (вне репозитория)

Агенты ссылаются на внешние инструменты из секции «Инструменты и skills»; их
ключи в дистрибутив не входят. Полный список — `INSTALL.md`, раздел «Внешние
зависимости профиля». Ключевое там:

| Что | У кого | Чем закрыть |
|-----|--------|-------------|
| `yandex-direct`, `yandex-marketing-apis-ru` | yandex-direct, analytics, performance, vk-ads | навыки Яндекс-стека из хаба + токен Директа/Метрики |
| `avito-api`, `ozon-seller-api`, `wildberries-api`, `MPSTATS` | avito, marketplaces, analytics, market-research | ключи кабинетов продавца |
| `DaData`, `YooKassa` | reputation, crm-retention, marketplaces | сервисы с API-ключами (MCP или HTTP) |

## Гигиена секретов

- Ключи живут в `.env` профиля (`cp .env.EXAMPLE .env`) — он в `.gitignore` и при
  `hermes profile update` не перезаписывается.
- В репозиторий ключи не попадают: `scripts/check_dist.py` ищет следы живых
  ключей в собранных дистрибутивах и валит сборку. Это последний барьер, а не
  замена дисциплине — `.gitignore` внутри дистрибутива ничего не защищает.
- Документация и `.env.EXAMPLE` намеренно содержат только имена переменных;
  строки-плейсхолдеры (`sk-...`, `<впишите>`) проверкой не считаются секретом.
- Клиентские ключи не храните в `company-brain/`: рабочий слой бизнеса —
  `company-brain/local/` (вне git).
