# Переупаковка: один материал, разные площадки

Один текст, размноженный по каналам, — это дубликаты. Один материал, переупакованный под
формат каждой площадки, — это дистрибуция. Разница в том, меняется ли хук, структура и длина при
сохранении фактов.

## Когда применять

- есть статья, кейс, исследование и нужно 3–7 версий под разные площадки
- «сделай из этого посты», «адаптируй под Telegram и VK»
- продолжение `article-distribution`: материал выбран для посева, нужны версии под площадки

**Не применять:** пост в сообщество с правилами (`community-post-generator`), календарь на
неделю (`content-calendar`), отправка (`publish-pipeline`).

## Что сохраняется, а что меняется

| Сохраняется всегда | Меняется |
|---|---|
| факты, числа, даты, имена | хук и первые 2 строки |
| смысл вывода | структура (список ↔ абзацы ↔ тред) |
| дисклеймеры и раскрытие авторства | длина |
| ссылка на источник | расположение ссылки (тело / первый комментарий) |
| UTM-метка кампании | тон (экспертный / разговорный) |

Правило: если при адаптации исчезло число или дисклеймер — это не адаптация, а искажение.

## Форматы площадок

| Площадка | Длина | Особенности | Частая ошибка |
|---|---|---|---|
| Telegram | 700–1200 знаков | короткие абзацы, ссылка в конце, эмодзи умеренно | простыня без абзацев и без вывода |
| VK | 1000–2000 | ссылки в теле допустимы, длинный текст читают | копия телеграм-версии без переработки |
| LinkedIn | 1200–1800 | одна мысль, без ссылок в теле (в комментарий), личный опыт | список из 12 пунктов без вывода |
| X / тред | 1 пост + 3–7 | хук в первой строке, нумерация, один факт на пост | тред-пересказ статьи абзацами |
| Email | 400–800 + тема | тема ≤ 60 знаков, прехедер, один CTA | несколько CTA в одном письме |
| Дзен | 2000+ | заголовок-вопрос, подзаголовки, картинки | заголовок-кликбейт |
| Хабр | 3000+ | техническая конкретика, без маркетинга | рекламный тон в техническом посте |
| Reddit | по правилам сабреддита | без промо, раскрытие авторства | ссылка на продукт в теле |

## Шаги

1. **Вытащить скелет источника**: 3–5 фактов с числами, один главный вывод, источник.
2. **Выбрать площадки** под задачу, а не «все сразу»: 2–4 достаточно.
3. **Для каждой написать хук заново** — с той же мыслью, но другим входом.
4. **Перестроить структуру** под формат: тред, список, письмо.
5. **Сверить с источником**: все числа и утверждения на месте, ничего не придумано.
6. **Добавить площадочные элементы**: UTM, подпись, теги, раскрытие.
7. **Отдать пакетом** с таблицей «что изменилось» — чтобы человек видел решения, а не только
   текст.

## Формат вывода

```markdown
## Источник
<название, ссылка, 3 главных факта с числами>

## Версии

### Telegram
<текст>

### LinkedIn
<текст>

## Что изменено и почему
| Площадка | Хук | Структура | Ссылка |

## Что нельзя сокращать
- <число> — на нём держится вывод
- <дисклеймер>
```

## Правила

- Каждая версия читается самостоятельно: без «как я писал выше».
- Один материал — один главный вывод. Если версий много, вывод один и тот же.
- Ссылка и UTM: одна кампания, разные `utm_source`.
- Не менять числа «для красоты» и не округлять в большую сторону.
- Не переносить чужие формулировки из источника без ссылки.

## Common Pitfalls

- **Один текст в пять каналов.** Лечение: минимум разный хук и структура в каждой версии.
- **Потерять дисклеймер при сокращении.** Лечение: список «что нельзя сокращать» в выводе.
- **Придумать факт, которого нет в источнике «для убедительности».** Лечение: сверка по скелету
  из шага 1.
- **Считать адаптацией смену эмодзи.** Лечение: меняются хук, структура и длина, а не украшения.
- **Писать версии без UTM.** Лечение: `utm_source` по площадке, иначе отдача не считается.

## Verification Checklist

- [ ] Скелет источника выписан (3–5 фактов с числами, вывод)
- [ ] Каждая версия имеет свой хук
- [ ] Структура отличается, смысл совпадает
- [ ] Все числа и дисклеймеры на месте
- [ ] UTM по площадкам
- [ ] Пакет отдан с таблицей «что изменено»
