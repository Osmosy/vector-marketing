# Yandex Wordstat (официальный API)

Семантика по реальному спросу в Яндексе: сколько раз за последние 30 дней искали фразу,
как меняется интерес по месяцам, из каких регионов идут запросы, какие фразы ищут рядом.

## Первоисточник, а не гайды

Публичного API у интерфейса `wordstat.yandex.ru` нет. Данные отдаёт **Yandex Cloud
Search API v2**: `https://searchapi.api.cloud.yandex.net/v2/wordstat/*`.
Контракт полей и лимиты — не из статей и обзоров, а из двух официальных источников:

- proto-контракт сервиса: `yandex/cloud/searchapi/v2/wordstat_service.proto`
  (репозиторий `yandex-cloud/cloudapi`) — обязательные поля, типы, enum'ы;
- квоты: `ru/_includes/search-api-limits.md` (репозиторий `yandex-cloud/docs`).

Детали контракта, коды ошибок и настройка доступа — `references/api-contract.md`.
Специфика рынка РФ (какие seed брать, чем Wordstat отличается от прогноза Директа) —
`references/rf-notes.md`.

## Когда какой метод

| Задача | Метод | Что отдаёт |
|--------|-------|-----------|
| Какие запросы есть по теме и сколько их | `topRequests` | топ фраз за 30 дней + **ассоциации** (то, что раньше называли «что ещё искали») |
| Растёт или падает интерес, сезонность | `dynamics` | частота по месяцам/неделям/дням + доля от всех запросов Яндекса |
| Гео: где спрос выше среднего | `regions` | разбивка по регионам/городам + **affinity index** (доля в регионе против доли по стране) |
| ID регионов для фильтра | `getRegionsTree` | дерево регионов; **бесплатный метод**, кэшируется на диск |

Ключевое отличие от ручного интерфейса: `topRequests` сразу возвращает **ассоциации** —
смежные запросы, которые не содержат исходную фразу. Это заготовка для расширения ядра,
которую в веб-интерфейсе приходится собирать глазами.

## Быстрый старт

```bash
# 1. Ключ: сервисный аккаунт Yandex Cloud с ролью search-api.webSearchUser,
#    затем API-ключ этого аккаунта (показывается один раз). Пошагово — references/api-contract.md.

# 2. Переменные окружения (в окружении или в .env профиля агента)
export WORDSTAT_API_KEY=...          # API-ключ сервисного аккаунта
export WORDSTAT_FOLDER_ID=b1g...     # ID каталога, ровно 20 символов

# 3. Прогон
python3 scripts/wordstat.py top "купить кофе в зернах" --num 100 --pretty
python3 scripts/wordstat.py dynamics "кофе в зернах" --period monthly --from 2025-09-01
python3 scripts/wordstat.py regions "кофе в зернах" --mode cities
python3 scripts/wordstat.py collect --seeds-file seeds.txt --num 200 --expand --out core.json
```

`collect` — основной рабочий режим: список seed-фраз, `--expand` раскрывает верхние
вложенные фразы вторым проходом (ядро вместо списка), `--out` пишет JSON, который дальше
идёт в кластеризацию и контент-план.

## Лимиты и деньги (проверено по официальной доке)

| Ограничение | Значение |
|-------------|----------|
| Запросов статистики в час | **100** |
| Запросов статистики в секунду | 10 |
| Фраз в ответе `topRequests` | `numPhrases` 1..2000, но API вернёт не более **250** |
| Ассоциаций в ответе | не более 20 |
| `getRegionsTree` | бесплатен, в лимит не входит |
| Оплата | депозит по факту запросов, не подписка |

Скрипт держит локальный счётчик в `~/.cache/wordstat/requests.json`: между запусками
он видит, сколько запросов ушло за последний час, и останавливает прогон **до** отказа
API (`--budget`, по умолчанию 90 из 100 — запас 10%). Прогон, который упирается в
`code 8`, теряет уже собранное, поэтому бюджет важнее скорости.

## Методика: от темы к ядру

1. **Seed.** Берите 5-15 фраз из разных слоёв, иначе ядро перекосит:
   категория («купить кофе в зернах»), проблема («кофе горчит что делать»),
   аудитория («кофе для офиса»), конкурент/бренд, гео («кофе с доставкой спб»).
   Из сайта seed не берётся автоматически — это отдельный шаг (краулер/карта страниц).
2. **Расширение.** `topRequests` по каждому seed: топ-фразы + ассоциации. `--expand`
   даёт второй уровень вложенности по самым частотным фразам.
3. **Чистка.** Уберите нерелевантное, брендовый мусор, инфозапросы, которых не
   закроете контентом. Минус-слова для Директа соберите отдельно: они нужны, но в
   SEO-ядре это балласт.
4. **Интент.** Разметьте коммерческие / информационные / навигационные: для SEO это
   разные страницы, для Директа — разные группы объявлений.
5. **Кластеризация** — отдельный шаг: `skills/searchfit-seo/keyword-clustering`
   (кластеры по интенту и SERP-пересечению) или `skills/open-seo/` (апстрим-навыки
   `keyword-clustering`, `keyword-research`).
6. **Сезонность.** `dynamics --period monthly` по 1-2 главным фразам кластера: пики
   спроса задают календарь публикаций и ставки; спад — повод не паниковать из-за
   просадки трафика.
7. **Гео.** `regions` + `affinityIndex`: >1 — спрос выше среднего по стране, там
   локальный лендинг/региональная кампания окупаются раньше.

## Как это используется в агентстве

- `seo` — ядро → кластеры → структура страниц и брифы (`content-brief`);
- `content` — темы статей и их приоритет по частоте, сезонный календарь;
- `yandex-direct` — семантика и минус-слова, группы объявлений, регионы показа;
- `market-research` — оценка размера спроса для market-sizing;
- `avito` — частотные формулировки для заголовков объявлений.

## Питфоллы (все проверены на живом API)

- `numPhrases` **обязателен**: без него `code 3`, «Value must be in the range of 1 to 2000».
  Значение больше 250 не ошибка — API молча вернёт усечённый список.
- `dynamics` требует **и** `period`, **и** `fromDate`; `period` — enum
  (`PERIOD_MONTHLY`/`PERIOD_WEEKLY`/`PERIOD_DAILY`), строка `monthly` не принимается.
- Все числовые поля приходят **строками** (protobuf JSON-маппинг): `int(count)` перед
  арифметикой; скрипт это делает сам.
- `folderId` — ровно 20 символов: пробел, приклеенный из интерфейса, ломает запрос.
- Ошибки API приходят с HTTP 4xx/2xx и телом `{code, message}`; ориентироваться нужно
  на `code` (3 — валидация, 8 — квота, 16 — ключ), а не на HTTP-статус.
- Данные всегда за **последние 30 дней** — это не «средняя частотность за год».
  Годовой профиль даёт только `dynamics`.

## Guardrails

- Не выдумывай частотность. Нет прогона — нет чисел: пиши «нужен запуск», а не оценку.
- Не выдавай «всего за 30 дней» за месячную частоту конкретной фразы: `totalCount` —
  сумма по всем фразам, вложенным в seed, без учёта порядка слов.
- Не сравнивай частоты, собранные с разными `regions`/`devices` — это разные знаменатели.
- Ключ — сервисный, не пользовательский OAuth; не храни ключ в репозитории
  (`scripts/check_dist.py` ловит утечки в дистрибутивах, но это последний барьер).
