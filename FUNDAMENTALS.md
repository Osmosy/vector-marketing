# Fundamentals — Context → Harness → Loop

Адаптировано из фреймворка [@shannholmberg](https://x.com/shannholmberg) / Nous Research под архитектуру Vector Marketing (Osmosy).

## Суть

Каждый хороший агент построен из трёх слоёв. Bot Mode / Hermes Profile — это упаковка. Реальная ценность — в том, что внутри.

---

## Слой 1 — Context (что модель видит в этом запуске)

Модель работает только с контекстным окном текущего запуска. Между запусками она ничего не помнит сама.

### Источники контекста

| Источник | Что содержит |
|----------|-------------|
| **Company Brain** (внутренний) | прошлые кампании, стратегия, офферы, бренд-войс, anti-slop правила, медиа-лист, примеры "как надо" |
| **Research агент** (внешний) | конкуренты, каналы, тренды, SERP, вопросы аудитории, что цитируется в AI-ответах |
| **Человек / текущая задача** | бриф, угол, канал, аудитория, taste-call, sign-off |

### Навык (skill) решает

Какой срез контекста загружается для текущей задачи:

- Content skill → бренд-войс + примеры + anti-slop
- SEO skill → бриф + SERP notes + прошлый ранжируемый контент
- Performance skill → оффер + ICP + цифры прошлого периода

### Практическое правило

Держите `company-brain/` богатым и актуальным. Это общий knowledge layer для всех 19 агентов.

## Слой 2 — Harness (что позволяет агенту действовать)

Модель сама по себе только генерирует текст. Harness — это то, что позволяет агенту загрузить навык, вызвать инструмент, сохранить файл, остановиться для подтверждения.

В архитектуре Vector Marketing harness — это **Hermes profile + skills + tools + MCP-коннекторы**.

### Компоненты harness

1. **Модель**
   Дешёвая/быстрая для throughput (deepseek-v4-flash:cloud). Сильнее для review и taste-work (deepseek-v4-pro).

2. **Skills**
   Процедуры, которые агент загружает для задачи: шаги, файлы для чтения, инструменты для вызова, критерий "готово".

3. **Инструменты**
   Что агент может делать: браузер, web_search, файлы, скрипты, MCP-коннекторы (DaData, Метрика, Директ).

4. **Коннекторы**
   Хуки в стек клиента: CRM, CMS, Search Console, рекламные кабинеты, email, аналитика.

5. **Память**
   Что агент хранит между задачами: заметки, логи прогресса, прошлые результаты по своему профилю.

6. **Роль + Voice rules**
   Идентичность, за какой результат отвечает, что НИКОГДА не делает (never-do list).

7. **Контроль**
   Бюджеты, таймауты, sign-off gates. Что агент может сделать без человека, а что нет.

### Узкие инструменты + чёткие стопы = надёжные агенты

## Слой 3 — Loop (draft → check → retry)

Как агент работает, пока результат не пройдёт quality bar.

```
СИГНАЛ СТАРТА (человек или cron)
        ↓
     DRAFT  →  агент делает работу (context + tools)
        ↓
     CHECK  →  pass/fail rubric (anti-slop, brand voice, бриф)
        ↓
     ROUTE  →  pass = handoff / ship
              miss = обратно к draft (бюджет ограничен)
              escalate = sign-off человека
```

### Примеры циклов в Vector Marketing

| Цикл | Rubric / done state | Notes |
|------|---------------------|-------|
| Content | Anti-slop + brand voice чеклист | Очередь на одобрение перед публикацией |
| SEO/GEO | Бриф + extractable answer blocks + entity consistency | Замер позиций после публикации |
| Performance | Тесты → чтение метрик → корректировка креатива | Стоп при превышении бюджета |
| Research | Структурированные выводы + источники + импликации | Может работать по cron (ночной скрапинг) |

### Scheduled / cron циклы

| Период | Задача | Агент |
|--------|--------|-------|
| Ночно | Скрапинг конкурентов и каналов | market-research |
| Ежедневно | SEO/GEO visibility check | seo |
| Еженедельно | Контент-пакет по стратегическим столпам | content |
| Еженедельно | Performance + следующие тесты | performance + landing-cro |

## Порядок сборки

1. Заполнить company-brain/ реальными данными бренда
2. Создать профиль Hermes на каждого агента, подключить skills и инструменты
3. Добавить loop с чётким done state (включая cron где возможно)

**Bot mode / Hermes profile — это упаковка. Рва — в контексте, который вы заложили.**
