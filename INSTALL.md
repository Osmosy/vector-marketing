# Установка и использование

Пошаговое пояснение для того, кто ставит агентство себе: что это, что именно
устанавливается, как запускать, что произойдёт при обновлении и где ограничения.

## Что это

Vector Marketing — маркетинговое AI-агентство из 19 агентов на базе
[Hermes Agent](https://github.com/NousResearch/hermes-agent). В этом репозитории лежит
**содержание агентов**, а не готовая программа:

- `agents/*.md` — SOUL-манифесты (роль, инструменты, формат выдачи, правила, guardrails, handoff);
- `company-brain/*.md` — общий контекст: голос бренда, anti-slop правила, стратегия, офферы, каналы;
- `skills/` — профильные навыки, на которые ссылаются агенты;
- `workflows/` — протокол передачи задач между агентами.

Из этого `scripts/build_profiles.py` собирает **дистрибутивы Hermes-профилей** — по одному на
агента. Профиль ставится командой `hermes profile install`, живёт в `~/.hermes/profiles/<agent>/`
и запускается как обычный Hermes-агент со своим SOUL и своими навыками.

## Требования

- Hermes Agent CLI (`hermes --version`), установка — см. документацию Hermes;
- Python 3.9+ (`python3 --version`) — для скриптов сборки и валидации;
- git — чтобы клонировать репозиторий;
- ключ хотя бы одной модели (любой провайдер, который поддерживает Hermes).

## Быстрый старт

```bash
git clone https://github.com/Osmosy/vector-marketing.git
cd vector-marketing

# 1. Собрать дистрибутивы (19 каталогов в dist/)
python3 scripts/build_profiles.py --clean

# 2. Поставить нужные профили
hermes profile install ./dist/orchestrator --alias   # оркестратор
hermes profile install ./dist/seo --alias            # и любые другие

# 3. Прописать ключ модели в профиле
cp ~/.hermes/profiles/seo/.env.EXAMPLE ~/.hermes/profiles/seo/.env
#   открыть .env и вписать ключ

# 4. Запустить
hermes -p seo chat
# или через оркестратор, который сам делегирует профильным агентам:
hermes -p orchestrator --skills vector-work "Клиент: интернет-магазин. Задача: +30% заявок."
```

`--alias` создаёт короткую команду, и дальше можно писать просто `seo chat`.

## Что попадает в профиль

| В профиле | Откуда | Перезаписывается при обновлении |
|-----------|--------|-------------------------------|
| `SOUL.md` | `agents/<agent>.md` + блок про общий контекст | да |
| `brain/*.md` | `company-brain/` (7 файлов) | да |
| `skills/…` | профильные навыки агента из `skills/` | да |
| `distribution.yaml` | генерируется (name, version, env_requires) | да |
| `config.yaml` | **не поставляется** — настраивается на месте | нет (сохраняется) |
| `.env` | создаётся вами из `.env.EXAMPLE` | нет (никогда) |
| `memories/`, `sessions/` | ваши диалоги и память | нет (никогда) |
| `local/` | ваши локальные переопределения | нет (никогда) |

Проверено на живом профиле: правка `SOUL.md` после `hermes profile update` затирается, а
`memories/`, `local/` и `config.yaml` остаются как были.

## Модель и ключи

Дистрибутив намеренно **не несёт `config.yaml`**: Hermes сохраняет локальный конфиг при
обновлении, поэтому отгруженный конфиг был бы навсегда перекрыт вашим и только путал бы.
Модель и провайдер выбираются один раз на месте (`hermes -p <agent> setup` или правка
`config.yaml` профиля), а секреты идут через `.env`.

Установщик сам создаёт `.env.EXAMPLE` со списком переменных из манифеста и при установке
печатает по каждой: `required` и `needs setting`. Модель в эти переменные не входит —
это настройка, а не секрет.

## Обновление

```bash
cd vector-marketing && git pull        # свежие SOUL, навыки, brain
python3 scripts/build_profiles.py      # пересобрать dist/ (без --clean тоже можно)
hermes profile update seo              # применить к профилю
```

`hermes profile update` берёт источник, записанный в манифесте профиля (для локальной установки
это путь к `dist/seo`), и заменяет содержимое дистрибутива. Ваши память, сессии, `.env`,
`config.yaml` и `local/` не трогаются. Сбросить ещё и конфиг: `hermes profile update seo --force-config`.

## Удаление

```bash
hermes profile delete seo
```

Перед удалением Hermes показывает происхождение профиля (дистрибутив, версию, источник) и
просит подтверждение. Память и сессии профиля удаляются вместе с ним.

## Ограничения, о которые легко споткнуться

- **Установка прямо по git-URL требует манифеста в корне репозитория.** `hermes profile install github.com/user/repo` клонирует репозиторий и ищет `distribution.yaml` в корне клона; конструкции вида `…#dist/agent` не поддерживаются. Здесь `dist/` — артефакт сборки (в `.gitignore`), поэтому профили ставятся локально из `./dist/<agent>`. Хотите раздавать агента по ссылке — заведите отдельный репозиторий и положите в его корень содержимое `dist/<agent>/`.
- **Имя профиля берётся из манифеста** и должно быть валидным id: `[a-z0-9][a-z0-9_-]{0,63}`. Зарезервированные имена (`hermes`, `default`, `test`, `tmp`, `root`, `sudo`) отклоняются. Переопределить: `--name другое-имя`.
- **Повторная установка поверх существующего профиля отклоняется** — это защита от затирания. Обновлять: `hermes profile update <agent>`; намеренно перезаписать: `--force`.
- **`.gitignore` внутри дистрибутива ничего не защищает** — установщик его не читает, файл просто копируется как есть. Секреты не должны попадать в репозиторий до сборки.
- **Симлинки в дистрибутиве запрещены** установщиком — на всякий случай проверяйте перед публикацией (`scripts/check_dist.py` это делает).
- **Агенты не наследуют конфиг друг от друга** — это осознанная изоляция профилей в Hermes. Общий контекст передаётся данными: `brain/` внутри каждого профиля.

## Если хотите править агентов под себя

1. Правьте `agents/*.md`, `company-brain/*.md`, `skills/`.
2. Прогоните проверки — они же гоняются в CI:

```bash
python3 scripts/validate_agents.py   # секции SOUL, @handoff, ссылки на навыки, таблица в README
python3 scripts/build_profiles.py --clean
python3 scripts/check_dist.py        # форма собранных дистрибутивов
```

3. `hermes profile update <agent>` — применить к своим профилям.

Валидатор намеренно строгий: он валит сборку, если `@handoff` ссылается на агента, которого нет,
если ссылка на навык не разрешается в дереве `skills/`, если у агента нет обязательной секции
SOUL или если таблица агентов в README разошлась с `agents/`.
